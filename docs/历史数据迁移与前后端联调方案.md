# 历史数据迁移与前后端联调方案（灵感速记 / 办公任务 / 项目表）

> 版本：v1.0 ｜ 日期：2026-10-20 ｜ 状态：待评审（含 3 个决策点，见 §7）
> 范围声明：本次**只**迁移【灵感速记表】【办公任务】【项目表】三类已有数据并完成前后端联调；
> 冗余数据清理、成员/计划/设置等其余数据迁移不在本期范围。

---

## 1. 数据源盘点（实测，非推测）

历史数据存于资料库「个人办公工作台」页面下的三张在线表，已于本方案编写时全部导出为 CSV
（本地留档：`E:/tmp/wbdata/{note,task,project}_raw.csv`）：

| 资料库表 | nodeId | 行数 | 字段（CSV 表头实测） |
|---|---|---|---|
| 灵感速记表 | cFKm2XkMZlDtNFV2c4VKK4 | 1 | 日期, 内容, 标签, 备注, 修改历史(JSON) |
| 办公任务 | L82S5NKN72AdpysR7zMEsc | 58 | 标题, 优先级(1/2/3), 截止日期, 是否完成(true/false), 所属项目(名称文本，可空), 创建日期 |
| 项目表 | 4eZwSnNL8r05SjWU4CNlwA | 16 | 项目名称, 当前阶段, 下一步, 卡点, 状态(中文) |

数据特征与陷阱：
- 办公任务标题含换行与 `☑️` 等符号（多行 CSV 引号包裹），迁移时须保留原文；
- 办公任务的「所属项目」是**项目名称文本**（非 ID），且存在空值（未关联项目）；
- 项目表「状态」为中文自由文本（实测全部为「进行中」，但不得假设只有这一种）；
- 灵感速记「修改历史」为 JSON 数组（ts/text/tags/remark），本期不迁，仅取最新 ts 作 UPDATED_AT。

## 3. 字段映射设计

### 3.1 灵感速记表 → WB_NOTE（1 条）

| CSV 字段 | 目标列/字段 | 转换规则 |
|---|---|---|
| 日期 | CREATED_AT | ISO 时间直转 TIMESTAMP |
| 内容 | CONTENT | 原文；同时若内容很短可截首句填 TITLE（≤500 字符），否则 TITLE 置 NULL |
| 标签 | TAGS | 逗号分隔字符串（≤500） |
| 备注 | CONTENT | 拼接在正文尾部：`正文\n\n【备注】…`（WB_NOTE 无独立备注列） |
| 修改历史 | UPDATED_AT | 取数组内最大 `ts`（epoch 毫秒）转 TIMESTAMP；JSON 本体不迁 |
| — | PINNED | 固定 0 |
| — | ID | 迁移工具生成 uid（与前端 uid 规则一致，32 位随机） |

### 3.2 办公任务 → WB_ITEM（58 条，KIND='task'）

| CSV 字段 | 目标列/字段 | 转换规则 |
|---|---|---|
| 标题 | TITLE | 原文（含换行、☑️），≤500 字符 |
| 优先级(1/2/3) | PRIORITY | **D1 决策**（默认）：1→`p0`、2→`p1`、3→`p2`（1 为最高） |
| 截止日期 | DUE_TIME | ISO 直转 |
| 是否完成 | STATUS | true→`done`；false→`todo`。done 时 COMPLETED_AT 置 NULL（CSV 无完成时间） |
| 所属项目 | PROJECT_ID | 按「项目名称」**精确匹配（trim 后）** WB_PROJECT.NAME → 取其 ID；空值→NULL；匹配不到→**D3 决策** |
| 创建日期 | CREATED_AT | ISO 直转 |
| — | TYPE / ASSIGNEE / NOTE / LAST_REMIND | NULL（CSV 无对应数据） |

### 3.3 项目表 → WB_PROJECT（16 条）

| CSV 字段 | 目标列/字段 | 转换规则 |
|---|---|---|
| 项目名称 | NAME | 原文（≤200 字符） |
| 状态 | STATUS | 中文→枚举映射：计划中→`plan`、进行中→`doing`、测试/验收中→`test`、已完成/已上线→`done`；未识别值→`doing` 并记入待复核清单 |
| 当前阶段 | NOTE | **D2 决策**（默认）：三段拼入 NOTE，格式 `【当前阶段】…\n【下一步】…\n【卡点】…`（卡点为空则省略该行） |
| 下一步 | NOTE | 同上 |
| 卡点 | NOTE | 同上 |
| — | OWNER / START_DATE / END_DATE | NULL（CSV 无） |
| — | ID | 迁移工具生成 uid；**先导项目、后导任务**，保证任务的 PROJECT_ID 可解析 |

> 映射执行顺序：① 项目表→WB_PROJECT（含生成 名称→ID 对照表）→ ② 办公任务→WB_ITEM（借对照表解析 PROJECT_ID）→ ③ 灵感速记→WB_NOTE。三步均在**同一事务/同一批 PUT** 内完成，保证引用一致。

## 4. 迁移通道选择

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A. 快照接口导入（推荐）** | Python 把 3 份 CSV 合成为 `SnapshotDTO` JSON（items/projects/notes），`POST /api/auth/login` 取 token → `GET /api/wb/snapshot` 确认为空 → `PUT /api/wb/snapshot` 一次提交 | 零后端改动；复用已验证的 saveSnapshot 事务与 USER_ID 归属；可整体重跑（先校验空库再 PUT） | 需要一个有效账号的 token | ✅ 采用 |
| B. JDBC 直写 | 仿 RunWbDdl 写 WbImport.java 直插三表 | 不依赖登录 | 绕过应用层校验与审计字段；与快照语义脱节 | 备用 |

方案 A 前提校验：`saveSnapshot` 为**整表替换**（先删后插当前用户数据），新库为空时 PUT 即纯插入，安全。

## 5. 迁移执行步骤（方案 A 落地清单）

1. **P1 转换脚本**：`tools/wb_import.py`
   - 读 3 份 CSV → 按第 3 节映射生成 `snapshot.json`（projects 16、items 58、notes 1）；
   - 输出**迁移预览报告**：行数、枚举映射结果、项目名匹配结果、未识别状态清单、超长字段截断告警；
   - 只生成文件，不联网。
2. **P2 导入执行**：
   - `POST /api/auth/login` 取 token（用现有系统账号，口令不入库不入文档）；
   - `GET /api/wb/snapshot` → 断言 projects/items/notes 全为 0（防重复导入）；
   - `PUT /api/wb/snapshot` 提交 snapshot.json；
   - `GET /api/wb/snapshot` 回读。
3. **P3 回读比对（迁移验收）**：
   - 行数校验：projects=16、items=58、notes=1；
   - 内容校验：转换脚本对每行生成 `md5(title+status+due+priority)` 指纹，与回读快照逐行比对；
   - 引用校验：items 中每条非空 projectId 必须存在于 projects 集合；
   - 新库直查兜底：`SELECT COUNT(*) FROM WB_ITEM WHERE USER_ID=:u` 等三条 SQL 与接口返回一致。
4. **P4 前端切换联调**（见 §6），切换后原 localStorage 数据保留一次作为比对底稿，验收通过后再清理（不在本期）。

## 6. 前后端对接接口设计（联调用）

### 6.1 通用约定

- BaseURL：`http://<host>:18077`（本机开发 `http://localhost:18077`；不使用 77/78，后者为浏览器封锁端口）；
- 除登录外所有请求带 `Authorization: Bearer {token}`；
- 响应统一包裹：`{"code":200,"msg":"ok","data":…}`；非 200 取 `msg` 提示；
- USER_ID 服务端解析，前端不传、不可伪造。

### 6.2 登录与令牌

```
POST /api/auth/login
Body: {"username":"…","password":"…"}
→ data: { token: "…", /* 会话信息 */ }
```

前端策略：token 存 localStorage（键与业务数据分开）；401 时跳登录页；提供 `POST /api/auth/logout` 退出；
可用 `GET /api/auth/session/validate` 在启动时预检会话有效性，`POST /api/auth/session/extend` 续期。

### 6.3 业务数据快照（核心，本期三类数据全走这一对接口）

```
GET /api/wb/snapshot
→ data: {
    members:  [ {id,name,role,color} ],
    projects: [ {id,name,status,owner,start,end,note} ],
    items:    [ {id,kind,title,type,projectId,assignee,priority,due,status,note,createdAt,completedAt,lastRemind} ],
    plans:    [ {id,title,period,items:[…]} ],
    settings: {…} | null,
    notes:    [ {id,title,content,tags,pinned,createdAt,updatedAt} ]
  }

PUT /api/wb/snapshot        // 整表替换：服务端先删当前用户旧数据再整体插入，幂等
Body: 与 GET 的 data 同构（允许只传 projects/items/notes，其余传空数组）
→ data: null
```

时间字段（due/createdAt/completedAt 等）为 ISO 字符串或 null；`lastRemind` 为 epoch 毫秒或 null；
枚举取值域（小写）：items.kind=`daily|task`、status=`todo|doing|done|cancel`、priority=`p0|p1|p2`、
projects.status=`plan|doing|test|done`。

### 6.4 灵感速记单独 CRUD（可选增强，快照之外细粒度操作）

```
GET    /api/wb/notes          → data: NoteDTO[]
POST   /api/wb/notes          body: {title?,content?,tags?}       → data: NoteDTO
PUT    /api/wb/notes/{id}     body: 同上                          → data: NoteDTO（404=不存在或无权）
DELETE /api/wb/notes/{id}                                          → data: null
```

### 6.5 前端（个人办公工作台.html）改造点

| # | 改造点 | 设计 |
|---|---|---|
| 1 | 启动加载 | 登录成功后 `GET snapshot` → 以云端数据渲染；首次且云端为空时，把现有 localStorage 数据整包 `PUT` 上去（即完成"前端存量自动上云"，与 §5 的 CSV 导入二选一或互补：**CSV 导入在库侧做，前端存量上云仅在云端为空时兜底，二者都先做空库断言防重复**） |
| 2 | 保存策略 | 本地每次变更后**防抖 2s** `PUT snapshot`（全量小数据，单用户场景）；PUT 失败进入重试队列（最多 3 次退避），期间界面标"未同步" |
| 3 | 离线兜底 | 请求失败时继续写 localStorage（现行为不变），恢复后整体 PUT 覆盖；单用户"最后写入胜出" |
| 4 | 一致性护栏 | 页面卸载（beforeunload）用 `navigator.sendBeacon` 或同步 XHR 兜底推送一次；云端 GET 与本地 uid 集合做合并去重 |
| 5 | 灵感速记 | 本期随快照读写即可；`/api/wb/notes` CRUD 预留给后续增量优化 |

## 7. 待确认决策点

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 优先级映射错（D1）导致 58 条任务紧急度反转 | 迁移预览报告列出每条映射前后值，先评审再执行 |
| CSV 多行标题/特殊符号在传输中被破坏 | 转换脚本 JSON 序列化保真；回读指纹比对兜底 |
| 重复导入造成数据翻倍 | PUT 前 GET 空库断言；saveSnapshot 本身整表替换，具备幂等性 |
| ZHS16GBK 生僻字（☑️ 等 emoji）写入失败 | 已引入 orai18n；转换脚本预扫非 GBK 字符并列入报告，必要时替换为 `[x]` |
| token 过期中断导入 | 脚本捕获 401 自动重登录一次；仍失败即中止报告，不无限重试 |

## 9. 验收标准（本期完成定义）

1. 新库三类数据行数与资料库一致（16/58/1），回读指纹比对 100% 通过；
2. 前端登录后页面渲染数据与迁移前一致（今日待办、项目跟进 16 个、灵感速记 1 条）；
3. 前端增删改一项，刷新页面后仍存在（云端持久化生效）；
4. 断网操作不丢失（localStorage 兜底），恢复联网后数据上云；
5. 全程不提交 SVN（遵循现行纪律）。
